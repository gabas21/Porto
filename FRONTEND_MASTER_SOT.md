# 2. DESIGN TASTE & LUXURY AGENCY STANDARDS (ANTI-SLOP)

To eliminate the "generic AI-generated template" appearance, adhere strictly to these agency rules:

### 🚫 Banned Patterns
1. **No Pure Saturated Colors:** Never use raw `#ff0000`, `#0000ff`, `#00ff00`, `#ffff00`. Use tailored HSL palettes, calibrated gradients, or dark tinted bases (`#08090A`, `#0B0D11`, `#12141A`).
2. **No Generic Default Fonts:** Avoid standard system serif/sans without purpose. Prefer distinctive typography pairings:
   - **Display:** *Syne*, *Space Grotesk*, *Cabinet Grotesk*, *Outfit*, *Clash Display*.
   - **Body & Interface:** *Inter*, *Geist*, *Plus Jakarta Sans*.
   - **Code & Metadata:** *Geist Mono*, *JetBrains Mono*, *Space Mono*.
3. **No Heavy Black Drop Shadows:** Replace `box-shadow: 0 10px 30px #000` with layered ambient occlusion shadows:
   ```css
   box-shadow: 
     0 1px 2px rgba(0, 0, 0, 0.04),
     0 4px 12px rgba(0, 0, 0, 0.06),
     0 16px 32px rgba(0, 0, 0, 0.08);
   ```
4. **No Gratuitous Nested Cards:** Avoid "card-inside-card-inside-card". Use 1px subtle boundary borders (`border-white/[0.08]` or `border-black/[0.06]`) and generous whitespace padding (`gap-8`, `gap-12`, `p-8`).

### ✨ Luxury Elements (The WOW Factor)
- **Extreme Typographic Scale:** Hero display titles (`text-5xl` to `text-8xl` with tracking `-0.03em`) contrasted against tiny uppercase tracking subtitles (`text-[11px]` with `tracking-[0.2em] font-mono text-white/50`).
- **Multi-Layered Glassmorphism:** Real backdrop-filter blur (`16px - 24px`) coupled with inner subtle border highlight (`inset 0 1px 0 0 rgba(255,255,255,0.12)`).
- **Perpetual Micro-Interactions:** Buttons that scale subtly on press (`whileTap={{ scale: 0.98 }}`), smooth spring hover physics, and dynamic time/status indicators.

# 3. REDESIGN WORKFLOW & PRE-FLIGHT AUDIT CHECKLIST

When upgrading an existing webpage, follow this 2-phase workflow:

### Phase 1: Pre-Flight Visual Audit
- [ ] **Color Palette Inspection:** Are saturated primary colors present? Replace with calibrated dark/light palettes.
- [ ] **Typography Audit:** Is hierarchy flat? Introduce distinct display font + monospace metadata tags.
- [ ] **Card Nesting Check:** Are containers awkwardly boxed within boxes? Flatten with border dividers.
- [ ] **Motion Audit:** Does the UI feel static/lifeless? Add spring hover physics and smooth entry reveals.
- [ ] **Mobile Breakpoints:** Does the layout break or overflow horizontally on small viewports (<390px)?

### Phase 2: Systematic 4-Step Transformation
1. **Core Tokens & `globals.css` Upgrade:** Inject typography variables, custom scrollbars, and color tokens.
2. **Navigation Re-architecture:** Replace standard static bar with floating `GlassSurface` morphing pill.
3. **Key Interaction Injection:** Add `HoverImageReveal` to list items, magnetic cursor pull, or smooth page transitions.
4. **E2E Validation:** Run Playwright test suite to guarantee zero regression on forms, links, or responsive DOM trees.

# 6. MOTION & ANIMATION ENGINEERING ARSENAL

### 6.1 Spring Physics Parameters
Never use linear transitions for human-interactive elements. Use these calibrated physics presets:

```typescript
// Cursor Following / Tooltips / Hover Cards (Instant & Snappy)
export const snappySpring = {
  stiffness: 350,
  damping: 28,
  mass: 0.6
};

// Smooth UI Navigation / Floating Docks (Gentle & Organic)
export const organicSpring = {
  stiffness: 200,
  damping: 22,
  mass: 1.0
};

// Dramatic Page Transitions / Large Layout Shifts
export const dramaticTransition = {
  duration: 0.85,
  ease: [0.76, 0, 0.24, 1] // Custom Agency Cubic-Bezier
};
```

### 6.2 GPU Acceleration Rules
To prevent layout reflows and stuttering on low-power devices:
1. **Animate ONLY Composite Properties:** `transform` (`translate3d`, `scale`, `rotate`) and `opacity`.
2. **Apply `will-change` Judiciously:** Use `will-change: transform` only on actively animated elements, then remove when idle.
3. **Leverage CSS Sub-Pixel Rendering:** Add `backface-visibility: hidden` and `-webkit-font-smoothing: subpixel-antialiased` to smooth out rotating text/cards.

# 7. PRODUCTION COMPONENT RECIPES & IMPLEMENTATION SPECS

## 7.1 3D Interactive Physics Lanyard (R3F + Rapier)
- **Purpose:** Interactive 3D ID card with realistic elastic band physics that users
### Section 2: 3D & Shader Rendering Engine Architecture
- **Interactive 3D Lanyard Pass:**
  - Dynamic import (`ssr: false`) with `@react-three/fiber` and `@react-three/rapier`.
  - **Viewport-Aware Frameloop Pausing:** Uses `IntersectionObserver` with `frameloop={isInView ? 'always' : 'never'}` to pause WebGL and physics calculations to 0% GPU/CPU whenever user scrolls past the Hero section.
  - **Optimized DPR:** `dpr={[1, 1.5]}` for high fidelity without unnecessary multi-sample rendering strain.
  - **Power Preference:** `gl={{ powerPreference: 'high-performance' }}`.
- **Atmospheric CloudShader:**
  - GPU-accelerated Raymarched FBM WebGL canvas.
  - **Smart DPR Capping:** Capped at `1.25` DPR, reducing per-fragment noise calculations by ~75% with zero visible softness difference.
  - **Visibility Observer:** Pauses RAF animation loop when scrolled out of viewport.
  - **Precision Fallback:** `#ifdef GL_FRAGMENT_PRECISION_HIGH` ensures cross-device stability on all mobile and desktop GPUs. using `sphericalJoint` in `@react-three/rapier` to simulate band elasticity.
  - Dynamically render dynamic curve coordinates per frame using `MeshLine` and `useFrame`.
  - Apply impulse vectors on pointer drag events to simulate realistic physical inertia.

## 7.2 Hover Image Reveal with Spring Physics
- **Purpose:** Display floating preview card that tracks the mouse with silky inertia when hovering over a list of projects.
- **Dependencies:** `motion` (`motion/react` or `framer-motion`).
- **Implementation Logic:**
  ```tsx
  import { motion, useSpring, useMotionValue, AnimatePresence } from "motion/react";
  
  // Track raw cursor
  const mouseX = useMotionValue(0);
  const mouseY = useMotionValue(0);
  
  // Apply spring interpolation
  const smoothX = useSpring(mouseX, { stiffness: 280, damping: 24 });
  const smoothY = useSpring(mouseY, { stiffness: 280, damping: 24 });
  
  const handleMouseMove = (e: React.MouseEvent) => {
    mouseX.set(e.clientX);
    mouseY.set(e.clientY);
  };
  ```

# 10. DEVELOPER IDENTITY & STANDING PREFERENCES

> **Purpose:** Preferences in this section apply across every project regardless of scope, so the AI never needs to re-ask them. Update this section only when a preference genuinely changes — not per project.

### 10.1 Code Style & Language
- **TypeScript:** Always `strict: true`. No `any` unless explicitly justified with a comment.
- **Naming Convention:** `PascalCase` for components, `camelCase` for functions/variables, `kebab-case` for file names except component files (`PascalCase.tsx`).
- **Imports:** Absolute imports via `@/` alias, never deep relative chains (`../../../`).
- **Comments:** Only where logic is non-obvious. No decorative comment banners.

### 10.2 Library & Tooling Defaults
- **Package Manager:** `npm` (not yarn/pnpm) unless a project explicitly overrides this.
- **State Management:** Prefer React built-ins (`useState`, `useReducer`, `Context`) before reaching for external state libraries.
- **Forms:** `react-hook-form` + `zod` for validation, when a project needs form handling.
- **Avoid:** Redux (unless project already uses it), Moment.js (use `date-fns` or native `Intl`), jQuery.

### 10.3 Git & Workflow Conventions
- **Commit Style:** Conventional Commits (`feat:`, `fix:`, `refactor:`, `chore:`).
- **Branching:** Feature branches off `main`, never commit directly to `main` on collaborative projects.

### 10.4 Communication Preferences
- **Language:** Bahasa Indonesia untuk diskusi/penjelasan; kode, komentar kode, dan nama variabel tetap dalam Bahasa Inggris.
- **Tone:** Prefer concise direct answers over long preambles when giving technical explanations.

# 11. AI SCOPE BOUNDARIES & CONFIRMATION GATES

> **Purpose:** Defines what AI agents may execute autonomously vs. what requires explicit user confirmation first. Critical for Project Motion given RLS-sensitive Supabase data.

### 🟢 Safe to Execute Autonomously
- Creating/editing component files, styles, and client-side logic.
- Running `npm install` for additive dependencies already listed in Section 9.
- Writing/updating Playwright tests.
- Editing `PROJECT_BRIEF.md` and documentation files.

### 🟡 Requires Explicit Confirmation Before Executing
- Installing new dependencies not listed in Section 9.
- Modifying `globals.css` design tokens that affect the whole app.
- Any Supabase schema change (new tables, altered columns, new RLS policies).
- Deleting existing files or components (rename/refactor is fine; deletion is not).
- Changes to authentication logic or `auth.uid()`-scoped queries.

### 🔴 Never Execute Without Multi-Step Confirmation
- Database migrations that affect production data (`public.subscriptions`, `public.user_sessions`, etc.).
- Dropping tables, columns, or RLS policies.
- Rotating or regenerating API keys / Supabase Project Ref credentials.
- Force-pushing or rewriting git history on shared branches.
